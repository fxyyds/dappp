# 优化项目计划文档 Spec

## Why

现有 `doc/任务/任务拆分清单.md`（35 项任务）虽完整，但存在四个问题：
1. 未充分体现最新确认的 4 项决策（第一阶段仅订单流、展示全自研、本地 Git、无时间压力）
2. 缺少前置任务：首次 Git 提交、Flink Kafka/Doris 连接器 jar 准备
3. 状态标记混乱："已起草"与"已验证"混为 ✅（如 T1.1~T1.3 未启动验证却标完成）
4. 只有阶段划分，没有里程碑验收标准，无法判断"一个阶段算不算做完"

需要生成一份更合理的计划文档，作为后续执行的唯一依据。

## What Changes

- **重构** `doc/任务/任务拆分清单.md`：由"纯阶段制"改为"里程碑驱动 + 阶段任务"双层结构
  - 3 个里程碑（M1 核心链路跑通 / M2 功能模块齐全 / M3 交付就绪），每个附**验收标准**
  - 阶段任务保留编号体系（T0.x ~ T6.x），归入对应里程碑
- **补齐缺失任务**：
  - 新增 T0.7 首次 Git 提交（当前工作区有未提交文件）
  - 新增 T1.6 Flink 连接器准备（flink-sql-connector-kafka、flink-doris-connector 放入 lib）
- **修正状态语义**：状态细分为 ✅ 完成（已验证）/ 🔲 进行中（已起草待验证）/ ⬜ 未开始；T1.1~T1.3 从 ✅ 改为 🔲
- **同步决策**：模拟数据仅订单流、展示工具暂缓全自研等约束写入计划头部
- **同步** 设计文档第 11 章"开发计划"与任务清单对齐
- 保持文档命名规范：所有 .md 中文命名

## Impact

- 受影响文档：
  - `doc/任务/任务拆分清单.md`（重写）
  - `doc/设计文档/电商Hadoop数据实时处理系统_系统设计文档.md`（第 11 章更新）
- 受影响代码：无

## ADDED Requirements

### Requirement: 计划文档须以里程碑为骨架

计划文档 SHALL 包含 3 个里程碑，每个里程碑附明确的验收标准（可客观判定是否达成）。

#### Scenario: 检查项目进度
- **WHEN** 用户打开任务拆分清单
- **THEN** 能直接看到 M1/M2/M3 三个里程碑的当前状态与验收标准，无需通读全部任务

### Requirement: 计划须与已确认决策一致

计划文档 SHALL 体现：第一阶段模拟数据仅订单流；展示层全自研（DataEase/DataRoom 暂缓）；本地 Git 管理；无时间压力按质量推进。

#### Scenario: 核对数据链路范围
- **WHEN** 查看数据链路阶段任务
- **THEN** 数据生成器与 Flink 作业范围均标注"仅订单流"，无用户行为/营销流的 P0 任务

### Requirement: 任务状态语义准确

已起草但未验证的任务 SHALL 标记为 🔲（进行中），不得标记为 ✅（完成）。

#### Scenario: 查看基础设施任务
- **WHEN** 查看 T1.1~T1.3
- **THEN** 状态为 🔲 且完成说明注明"已起草，待启动验证"

### Requirement: 文档文件名使用中文

本次新建或重写的所有 .md 文档文件名 SHALL 使用中文。

#### Scenario: 新增文档
- **WHEN** 执行过程中产生新的文档文件
- **THEN** 文件名为中文（代码/SQL/脚本文件除外）
